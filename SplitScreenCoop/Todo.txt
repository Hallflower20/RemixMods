SplitScreen Co-op 0.2.2 status
================================

See HANDOFF.md for how the dynamic pipeline renders, the invariants that are easy
to break, the mechanism behind each recent fix, and how to build without a working
MSBuild. Read it before changing rendering code.

Implemented
-----------
[x] Automatic split mode with Remix options for permanent split and dual display.
[x] Smooth split-camera following.
[x] Stable camera ownership: player 1/player 2 remain left/right.
[x] Three-player triangle and four-player corner layouts.
[x] Black visual separators between split views.
[x] Multi-display fullscreen activation, menu mirroring, availability fallback.
[x] Independent room realizers for every remote player.
[x] Self-sufficient shared food and any-survivor karma progression.
[x] Self-sufficient shelter, starvation, game-over, and gate checks.
[x] Players captured into a den are considered missing for shelter/gate checks.
[x] Death gong for each player.
[x] Separate shelter persistence and wake placement within the loaded world/region.
[x] Player 2 karma-flower death position.
[x] Friends saved by non-primary players count at cycle end.
[x] Player 2 sign-in/input initialization without Jolly enabled.
[x] Watcher per-camera level textures, ripple buffers, masks, and shader keywords.
[x] Camera health diagnostics and stalled render-target recovery.
[x] Delayed room-camera resync after missed transitions.
[x] Split-camera map input no longer enters vanilla camera cycling.
[x] Adaptive layouts use only living players and reflow after deaths.
[x] Dividers composite under the HUD and pause menu instead of over them.
[x] Pause buttons and confirm text follow the view's actual HUD translation.
[x] HUD textures no longer smear their border into neighbouring cells.
[x] Native-scale views sample on whole texels, so following does not soften the image.
[x] A view that cannot legally pan far enough still keeps its slugcat on its own
    side of a divider, at the cost of a clamped edge strip.
[x] A dead player's camera no longer forces synchronous room resyncs while the
    corpse is carried.
[x] Dynamic layout is solved before the first frame after spawn-in.
[x] Palette changes from room effects, day/night and palette rooms are attributed
    to the camera that made them.
[x] Karma fade circles travel with the globally routed karma meter.

[x] A realizer can no longer abstractize a room another player, their camera or a
    shortcut vessel still needs. RemoveNotVisitedRooms bypassed CanAbstractizeRoom,
    which froze a player inside a pipe permanently.
[x] One shared pause menu on the global stage, at native coordinates, so the
    pointer lines up with what is drawn.
[x] Futile's root stage is composited again, which is where Menu.MouseCursor
    parents the cursor.
[x] All players inside one shelter collapse to a single view and a single HUD.
[x] Shader globals written from Room.Update are attributed to the cameras showing
    that room instead of leaking between views.
[x] Cameras loading the same room share a screen key, so spawn-in no longer opens
    split for a couple of frames.

[x] Layout cells are axis-aligned rectangles (2: side by side; 3: one half over
    two quarters; 4: a 2x2 grid; slots by camera number, see below). Each view
    samples one prebaked screen, and only a rectangle keeps
    enough pan to always show its own slugcat; the Voronoi cells could not, which
    is what the "player visibility correction" slack, the smeared edge strips and
    the per-frame jumps were compensating for. That slack is gone.
[x] Views pan every rendered frame from interpolated positions and are damped, so
    following no longer steps at the 40 Hz tick or snaps when a clamp toggles.
[x] The vanilla camera is left alone in Dynamic style; the mod no longer fights
    RoomCamera's own clamp every tick with a follow target it could never reach.
[x] Exiting to the menu no longer leaves a black screen: SetSplitMode stopped
    re-isolating camera 0's culling mask after ResetDynamicLayout restored it.
[x] Cameras that switch to a screen another camera already decoded copy its
    pixels instead of decoding the PNG again on the main thread.
[x] Room realizers share one performance budget (1500 + 750 per extra player) and
    may not abstractize a room another realizer still needs, which stopped the
    reload ping-pong of neighbour rooms between players.
[x] Frames over 50 ms are logged as [FrameHitch] with the room loads, camera moves
    and texture decodes that happened in them.
[x] Default view zoom is native scale (Remix key ViewZoomExponent = 0); raise it
    for zoomed-out cells.
[x] MSBuild builds again (csproj targets v4.8.1, matching the installed pack).

[x] Nothing fades any more. Two players on one prebaked screen merge the LEGO
    way: both cells keep drawing the same image and each cell's pan lerps from
    "centre my player" to "identity" as the split amount falls, so the halves
    line up and the divider vanishes; moving apart reverses it. The split
    amount is damped (0.25 s) so a player arriving on the other's screen
    through a pipe glides in instead of popping. Three or more cells slide from
    their old rectangles to their new ones over the resting layout when the
    grouping changes; a dying player's cut slides shut.
[x] Only base cameras render; a cell always draws the camera whose prebaked
    screen its players share, so merged views are one image, not a blend.
[x] A cell only starts drawing the other camera's image once its own camera is
    on that screen (the vanilla cut moment), and keeps sharing while its player
    stays visible there. Merging no longer swaps a cell to a different screen
    and swipes it into place; the line just fades as the pans converge.
[ ] Whole-process freezes (26-69 s frames, no [Hang]) in the twelfth log: not
    the mod's frame cost (p95 4 ms). Next log: look for "[Hang] the whole
    process stood still" and the renderTextures count; on the playtest PC
    check RAM use and Event Viewer for display-driver resets.
[x] Camera audit (HANDOFF §5 "Camera audit"): every named screen grab (17 of
    them; _SlopedTerrainMask alone feeds slush water and backgrounds) was
    camera 0's on the other cameras. World cameras now render one per frame
    (Auto while every view keeps 50 fps; Remix "Camera rendering"), so each
    frame has one grabbing camera. _tileCorrection (blizzard, dust wave) is
    recomputed per camera; environment-coloured lights, light beams, gold
    flakes, fairy particles, zero-g specks and OE clouds run with the viewing
    camera as cameras[0]. [ShaderAudit] logs any global written outside camera
    scope with the method that wrote it.
[x] Sleep/death screens no longer freeze on the last game frame when the
    surviving player was not camera 0 (listener 0 left in split mode kept
    copying its stale texture over the menu).
[x] A pause no longer trips the draw-stall detector on unpausing (paused draws
    count), and pass-through mode ends by itself after 600 healthy frames.
[x] The pause menu's cursor draws above the menu again (global HUD stage sits
    below Futile's root stage).
[x] Hidden AbstractSpaceVisualizer labels are removed at shutdown (the root
    stage grew by 500 per session).
[x] Revisited screens upload a cached level image instead of decoding the PNG.
[x] Cameras that skip DrawSprites while off still let objects retire their
    leasers (the skip had leaked every dead object's sprites on those cameras).
[x] Dynamic level elements (foliage, grass, rot tubes, candles) get their own
    per-camera grab: Unity's named GrabPass happens once per frame, so the
    other cameras had combined camera 0's grab into their level texture.
[x] A warp moves every camera, not only the precast one; a session resumed
    from a warp no longer leaves cameras 1-3 at room=null with the screen
    split around an empty cell.
[x] The unloaded-world cleanup skips cameras already loading a room, so a
    warp no longer strips the watched camera's ripple masks (broken colours)
    or empties the other cells.
[x] [Perf] heartbeat line and an "Extra rooms per player" Remix slider for the
    realizer budget.
[x] Sleep lockout after a region change (seventh playtest): a rot-spore renderer
    node of a camera left behind in the unloaded world held a destroyed
    GameObject; re-parenting that camera's layers at shutdown threw, the
    process switch aborted before clearing the current process, and the dead
    game was updated forever. Nodes now leave their containers before their
    GameObject dies, cameras left in an unloaded world drop their sprite
    leasers when the new world loads, the shutdown hook contains every
    exception, and [UnityLog] buckets by message plus top stack frames.
[x] Cameras that are not rendering skip DrawSprites for their room objects
    (three players in one room were three full draw passes per frame).
[x] Watcher foliage, grass and other dynamic level elements keep their colour
    on every camera. They are Unity mask meshes shared between cameras, and
    only the last camera to draw had them in view; the others composited a
    stale grab into their level texture. Each camera now places the meshes
    for itself right before it renders (CameraListener.OnPreCull).
[x] Cells sit in fixed slots by camera number (two: left/right; three: the
    merged pair or camera 0 on top, the others below; four: a grid) and only a
    merge, a part, an arrival or a death changes the layout. The rotating
    two-player divider, side swaps, axis flips, dead zones and hold times are
    gone: the screens no longer shift around with the players' positions.
[x] The divider's opacity is how far apart the two views are in world pixels
    (fading over 4 to 300 px, damped 0.2 s per pair), so it fades across the
    whole glide as views converge and is hidden when the two halves are already
    one continuous picture. Solid across rooms.
[x] Merging across a screen boundary in a wide room cannot be continuous (a half
    cell is wider than the overlap between adjacent screens), so the pan after
    the cut glides over 0.5 s instead of 0.25 s, with the line fading alongside.
[x] A living player being abstracted mid-pipe no longer counts as dead
    (IsCreatureDead dropped the slated-for-deletion clause). That false death
    removed their camera and, with the other player held or dead, ended the
    game with someone alive.
[x] The game-over prompt itself is gated: TextPrompt.EnterGameOverMode is
    refused unless every player is dead or held, whichever vanilla path raised
    it. "[Coop] blocked game-over prompt" logs each refusal with player states.
[x] A camera whose followed player is dead is muted regardless of layout state,
    in addition to cameras with no live cell.
[x] Cameras that are not in the layout (dead players, fading ghosts) are muted;
    their point of view no longer plays in the mix.
[x] Rot (Watcher "red goop") renders on every camera: vanilla UpdateRotMode
    always wrote the rot effect colours into cameras[0]'s palette, and Room.Update
    handed cameras[0] other rooms' rot amounts. Re-implemented per camera.
[x] Globals written while a room loads (RoofTopView's _SceneOrigoPosition and
    friends, the city backdrop) are kept in a per-room record and copied to a
    camera when it arrives in that room.
[x] Any player's map button reveals the shared meters, not only the owner of the
    camera whose HUD supplies them.
[x] Menu camera watchdog: while no game runs, camera 0 is forced enabled, on the
    screen texture, with the root stage in its mask, and every other camera off.
    "[MenuCamera]" logs what it had to correct plus a snapshot per process switch.
[x] Food pips are white again: the letterbox bars were routed onto the global
    stage after the meters, so they were drawn over the pips. The text prompt is
    routed first now, as vanilla builds it.
[x] Ghost (echo) and rot palette modes are mirrored onto every camera showing the
    room; Room.cs only ever updated cameras[0].
[x] The game-over and pause prompts win the global prompt slot outright, so the
    "Game Over - Press ... to restart" line cannot be left in an unrouted HUD.
[x] [Coop] log lines mark game over, the prompt camera and GoToDeathScreen, and
    the heartbeat carries each camera's palette state (palA/palB/blend/ghost/fog).

Build notes
-----------
The .NET Framework 4.8.1 Developer Pack is installed and both csproj files target
v4.8.1, so MSBuild/Visual Studio build normally. Pass /p:RainWorldPath so the
references resolve from the actual Steam folder (the hard-coded HintPaths point at
a drive that does not exist here). Mod/plugins/SplitScreen Co-op.dll is the
post-build copy of bin\Release.
